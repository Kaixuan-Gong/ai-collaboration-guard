# 安全红线

## 1. 先保护工作，再完成任务

- 仓库、分支、远端、操作范围不明确时先核实。不要为了权限探测而实际推送无关内容。
- 用只读预检辨认已暂存、未暂存、未跟踪、正在合并和 detached HEAD 等状态。预检是本地缓存，不证明远端最新。
- 未知文件或别人的工作不动；不自动 stash、提交、丢弃或搬运。
- 正常提交先看 `git status`、工作区 diff、暂存区 diff，按明确路径暂存，再确认暂存内容只属于本任务。
- `git add .` / `git add -A` 不作为默认操作；`.gitignore` 不是秘密扫描器，不能保护已经跟踪的文件。
- 不把普通 push 被拒当故障绕过：non-fast-forward 通常表示远端有本地未包含的历史。先核对，再合并，不能强推。

## 2. 不重写共享历史

- 主线、发布线、他人使用中的分支：禁止 force push、历史改写和为了同步而 reset。
- `reset --hard`、`clean`、覆盖还原、强删分支不能作为修复错误的捷径。
- 默认将已核实远端变更普通 merge 到自己的功能分支。只有确认为未发表且无人依赖的本地提交，才考虑 rebase。
- 本地未发表提交 rebase 后通常可以正常 push；不能说 rebase 后必然需要强推。
- 个人已发表分支的历史重写不属于默认新手流程。只有用户明确要求、确认无协作者依赖、保留备份且核对远端期望 SHA 后，才讨论带显式租约的操作。
- 分叉不是业务取舍：AI 应先检查并推荐保留双方历史的方案，不让新手在不理解含义时选 Git 术语。
- 两段逻辑互相矛盾、无法从需求判断时，用业务语言问用户，不能批量选择 ours/theirs。

## 3. 暂存不是自动备份

需要暂存时，先列出本次拥有的文件并核实没有秘密、未授权内容或另一任务的修改，再获得用户对保存方式的决定。

- stash 默认不含未跟踪文件。需要 `-u` 时必须确认哪些新文件会被收起，避免把秘密写入 Git 对象库。
- 说明 stash 的归属和用途，记录创建后的完整对象 SHA。
- 恢复前按该 SHA 查看内容，再执行 `git stash apply "$STASH_SHA"`；不要默认弹出最新一条。
- `stash@{n}` 是会随列表变化的引用，不是稳定 SHA；先 `git rev-parse 'stash@{n}'` 解析，再使用结果。
- apply 出现冲突时停止，保留 stash，不能删除唯一备份。确认恢复完整后才考虑清理自己的 stash。
- 本 Skill 的脚本不会自动替用户 stash。

## 4. 秘密和公开边界

首次发布前核查 `.env`、私钥、令牌、签名证书、数据库、备份和个人信息。不要擅自改变仓库公开性、上传未获授权的文件或共享账号凭证。

秘密进入历史时，先停止扩散并轮换/撤销秘密。只删当前文件不等于清除历史；历史清理另行确定范围，不能把强推当作普通协作步骤。

## 5. 真实审核，不伪造通过

- PR 作者不能正式批准自己的 PR；作者自检评论不算另一人的批准。
- 两个 AI 会话使用同一个账号，不算两个独立审批人；禁止借他人凭证冒充审核。
- 旧审批是否被 GitHub 自动撤销取决于仓库规则。无论是否自动撤销，base/head 变动后 AI 都要重新审查。
- `remote_check.sh` 的 OK 只是指定范围的机械查询完成，不代表测试、逻辑审查或合并审批通过。
- `conflict_check.sh` 的 CLEAN 只证明标准 Git 对两个提交的文本合并结果。UNKNOWN/LIMITED 一律不是通过。
- 脚本或 API 读取失败、缺少权限、分页不完整时记录 UNKNOWN，不能把“没查到”写成“没有问题”。

## 6. 仓库门禁需要真实配置

由有权限的维护者通过网页、CLI 或 API 配置，并回读验证：要求 PR、禁强推/删除、实际 CI 检查、按真实审核人数设置审批规则。权限、计划或设置不支持时明确是“工作约定”，不能称为“服务器已强制拦截”。参见 `gates-setup.md`。

安装 Skill 不会自动修改所有项目设置，也不会启动后台监听。只在用户授权的具体仓库中配置。不得为减少操作步骤而关闭已有保护规则。

## 7. 不把试合当安全沙箱

冲突脚本仅隔离 Git 机械预演，不是运行不可信业务代码的沙箱。不要在含生产凭证的环境运行来历不明的构建、测试、hook、filter 或 merge driver。实际测试需要可审查的命令与适合的隔离环境；无法测试就说明缺口。

任何脚本检查都有时间边界，不能保证没有其他进程同时操作。每个活跃 AI 用独立目录和分支；合并前刷新并比较准确 SHA；最后仍由服务器保护规则核验。
